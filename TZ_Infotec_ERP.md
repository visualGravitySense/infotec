# Техническое задание
## Разработка корпоративного сайта Infotec ERP

**Заказчик:** Infotec ERPsystem
**Референс-дизайн:** прилагаемый прототип главной страницы (HTML/Tailwind, "Infotec ERPsystem — Корпоративная ERP-экосистема")
**Дата:** aвгуст 2026
**Версия документа:** 1.0

---

## 1. Общее описание проекта

Разработка корпоративного веб-сайта Infotec  — маркетинговой платформы (не самого ПО), презентующей 12 модулей ERP-системы и 9 отраслевых готовых решений компании. Сайт выполняет функцию основного канала лидогенерации: презентация продукта, каталогизация модулей/решений, сбор заявок на демо-доступ.

Сайт разрабатывается как многоязычная (RU/EST/ENG) шаблонная система на **~28-30 страниц**, где итоговое количество страниц формируется за счёт клонирования небольшого набора уникальных шаблонов с разным содержимым (модули, отраслевые решения, новости), управляемым через headless CMS.

### 1.1 Цели проекта
- Презентовать экосистему из 12 ERP-модулей и 9 отраслевых решений в едином премиальном визуальном языке.
- Обеспечить самостоятельное редактирование контента заказчиком без участия разработчика.
- Обеспечить трёхъязычность интерфейса и контента (RU / EST / ENG).
- Заложить техническую базу для последующего добавления новых модулей/решений без пересборки дизайна.

### 1.2 Целевая аудитория
Руководители и ИТ-директора компаний малого и среднего бизнеса в странах Балтии, рассматривающие внедрение или замену ERP-системы.

## 3. Локализация (RU / EST / ENG)

- Технически реализуется через раздельные локали в структуре URL (например `/ru/`, `/et/`, `/en/`), с переключателем языка в хедере (элемент уже присутствует в прототипе — `nav-lang-wrap`).
- Один и тот же шаблон/дизайн-блок используется для всех трёх языков — различается только содержимое (текст, при необходимости — локализованные скриншоты интерфейса).
- **Объём перевода:** переводится весь текстовый контент всех ~28-30 страниц на 3 языка.
- **Зона ответственности за перевод контента и SEO-копирайтинг фиксируется отдельно** (см. раздел 9) — необходимо явно прописать в договоре, кто переводит: разработчик, отдельный переводчик или заказчик.
- SEO-метаданные (title, description, OG-теги, alt-тексты изображений) должны быть локализованы и редактируемы отдельно для каждого языка через CMS.

## 5. Описание шаблонов страниц и их блоков

### 5.1 Главная страница (уникальный дизайн, максимальная детализация)

На основе присланного прототипа, страница состоит из следующих блоков (сверху вниз):

1. **Header** — логотип, основное меню, языковой переключатель, кнопки «Войти» / «Демо-доступ», мобильное меню.
2. **Hero-секция** — заголовок с акцентным градиентным текстом, подзаголовок, форма захвата email, mockup продукта справа (изображение/интерактив).
3. **Trust-метрики (лента показателей)** — блок временно скрыт в прототипе (закомментирован), решить: включать ли в финальную версию.
4. **Case Studies (кейсы клиентов)** — интерактивные табы (4 примера компаний: SKS Estonia Textile, Riga Logistics SIA, Baltic Trade OÜ, EstMetall Grupp) с превью-изображением, переключаемым по клику.
5. **AI + ERP Flow** — премиальный сторителлинг-блок: пайплайн из 3 шагов + карточки преимуществ.
6. **Industry Solutions (превью)** — 4 карточки отраслей с фото (Производство, Торговля/ритейл, Логистика, Строительство).
7. **Модульный навигатор (12 модулей)** — интерактивный трёхколоночный блок: список модулей слева → карточка описания по центру → «программный терминал» (визуализация интерфейса: таблица данных, AI-метрики, график) справа. Переключение по клику/клавиатуре без перезагрузки страницы.
8. **Solutions Bento-grid** — карточки отраслевых решений разного размера (span 7/5) + чипы дополнительных вертикалей + CTA-форма «Не нашли свою отрасль?».
9. **News & Reviews** — блок новостей и отзывов клиентов.
10. **Footer** — контакты по офисам (Таллинн, Нарва), карта разделов сайта, соцсети, копирайт.

### 5.2 Каталог «ERP Модули» (список)

Сетка из 12 карточек-превью модулей (иконка/иллюстрация, название, краткое описание, ссылка на детальную страницу).

### 5.3 Детальная страница модуля (переиспользуемый шаблон ×12)

По аналогии с уже утверждённым прототипом «Управление продажами» (см. предыдущий макет Frame):
- Hero-блок модуля (заголовок, описание, интерактивная иллюстрация).
- Bento-grid из 5–6 карточек ключевых функций модуля (иконка + заголовок + описание).
- Блок «Ключевые возможности» — 3 карточки с CTA «Подробнее».
- Развёрнутый блок одной выбранной функции — скриншот реального интерфейса ПО (не абстрактная графика, заказчик предоставляет материалы) + список буллитов + аннотации к элементам интерфейса.
- CTA-блок в конце (форма/кнопка запроса демо).

**Важно:** структура блоков должна быть гибкой (drag/reorder в CMS), так как разные модули могут требовать разного количества карточек функций.

### 5.4 Каталог «Готовые решения» (список)

Аналогично каталогу модулей — сетка из 9 карточек отраслевых вертикалей (Производство, Торговля, Логистика, Строительство, Недоходный сектор, Квартирные товарищества, Общепит/HoReCa, Отели + 1 уточняется).

### 5.5 Детальная страница отраслевого решения (переиспользуемый шаблон ×9)

Похож на шаблон модуля, но с возможным дополнением специфичных блоков (например, для «Отелей» — блок с показателем occupancy, для «Логистики» — блок с картой/маршрутами). Базовая структура блоков должна совпадать минимум на 70% с шаблоном модуля для экономии времени разработки.

### 5.6 Новости / Блог

- Список: карточки новостей с датой, превью-картинкой, кратким текстом.
- Детальная страница поста: заголовок, дата, автор, тело статьи (rich text из CMS), изображения.

### 5.7 Информационные страницы

Контакты (адреса Таллинн/Нарва, телефоны, email, карта), Условия использования, Политика конфиденциальности. Единый простой текстовый шаблон.

## 7. Требования к CMS (Sanity Studio)

Заказчик должен иметь возможность самостоятельно, без участия разработчика:

1. Редактировать все текстовые поля (заголовки, описания, буллиты) на каждом из 3 языков раздельно.
2. Загружать/заменять изображения (скриншоты интерфейса, иллюстрации, фото) с автоматической оптимизацией.
3. Добавлять/удалять/переставлять карточки в Bento-grid и списках функций (drag-and-drop в админке).
4. Клонировать шаблон страницы модуля/решения для создания нового модуля из готового набора блоков.
5. Управлять пунктами меню (header) и структурой footer.
6. Управлять SEO-полями (title, description, OG-image) для каждой страницы и каждого языка.
7. Публиковать/снимать с публикации страницы (draft/publish workflow).

**Ограничение (защита от поломки вёрстки):** структура и вёрстка блоков остаются фиксированными компонентами кода — CMS отвечает только за контент (текст/изображения/порядок карточек), но не позволяет менять CSS/layout напрямую.

> Уточнить: возможность добавления/удаления отдельного буллита в списке (не только редактирование существующих) должна быть явно предусмотрена как повторяющееся поле (array) в схеме Sanity, а не как фиксированный набор из N полей.

| Иконки/иллюстрации функций (стиль 3D/изометрия, как на первом варианте прототипа) | Разработчик/дизайнер | ≈ 15-20 уникальных иконок (переиспользуются между модулями) |

**Критично:** во всех местах, где показан интерфейс программного продукта, должны использоваться реальные материалы Infotec (либо максимально приближенные к реальному UI), чтобы не вводить клиентов в заблуждение относительно вида финального ПО. Это зафиксировано как обязательное условие.

## 9. Контент и SEO-копирайтинг

- Тексты для карточек, описаний модулей и решений пишет разработчик по согласованию и под руководством заказчика (конверсионный/SEO-текст).
- **Необходимо зафиксировать:**
  - Количество раундов правок текста, включённых в стоимость (рекомендуется 2–3 итерации).
  - Язык, на котором изначально пишется текст (предполагается русский), и то, каким образом выполняется перевод на EST/ENG — включён ли перевод в стоимость копирайтинга или тарифицируется отдельно (переводчиком/агентством).
  - SEO-требования: мета-теги, семантическая структура заголовков (H1-H2-H3), alt-тексты изображений, микроразметка Schema.org (Organization, Product/Service) — желательно для B2B ERP-тематики.

## 10. Функциональные требования

- Интерактивный переключатель модулей на главной странице без перезагрузки (используется существующий JS-паттерн из прототипа — `renderModuleView`).
- Табы кейсов клиентов с плавным переключением превью.

- Адаптивная вёрстка: desktop / tablet / mobile, включая мобильное меню (уже частично предусмотрено в прототипе — `mobile-nav-link`).
- Языковой переключатель (RU/EST/ENG) с сохранением текущей страницы при смене языка.
- SEO: серверный рендеринг (SSR/SSG через Next.js) для индексации поисковыми системами на всех 3 языках.

## 12. Этапы работы (предлагаемая структура)

1. **Дизайн-система и брендинг** — финализация стиля на основе прототипа.
2. **Дизайн уникальных шаблонов** (≈ 8 шт., см. раздел 4) — по одному макету на каждый тип страницы.
3. **Вёрстка/разработка + интеграция Sanity CMS** — сборка компонентов, настройка схем контента.
4. **Наполнение контентом** — клонирование страниц модулей/решений на основе готовых шаблонов и переданных текстов/изображений.
5. **Локализация** — техническая настройка i18n + подключение переведённого контента.
6. **SEO-настройка** — метатеги, sitemap.xml, robots.txt, микроразметка.
7. **Тестирование** — кроссбраузерность, адаптивность, скорость загрузки (Core Web Vitals).
8. **Приёмка и передача доступов.**

## 13. Критерии приёмки

- Все ≈ 28-30 страниц опубликованы на 3 языках и доступны по локализованным URL.
- Все текстовые и графические элементы редактируются заказчиком самостоятельно через Sanity Studio без обращения к разработчику.
- Скриншоты интерфейса ПО в согласованных местах заменены на реальные материалы заказчика.
- Сайт корректно отображается на desktop/tablet/mobile.
- Формы захвата лидов работают и передают данные в указанный канал (email/CRM).
- Заказчику переданы: доступ-владелец к Sanity-проекту, репозиторий кода, документация/инструкция по CMS.
